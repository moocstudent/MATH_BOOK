# 四种装柜方式 — 理解与架构草案

> 本文档基于 LoadExpert 类产品常见模式整理,供后续逐项细化规则与 UI。

## 现状 (Demo 当前行为)

| 能力 | 状态 |
|------|------|
| 多种货物 + 固定数量 | ✅ |
| 多种集装箱 + 每行 `count` 柜数 | ✅ (无「箱型上限」、无运费) |
| 单柜内 3D 码放 + 门侧策略 | ✅ |
| 装柜顺序 (里→外) | ✅ 按 `stack_level` / 易碎后装 |
| 运费最优组合 | ❌ |
| 多方案对比输出 | ❌ |
| 体积比装载 | ❌ |
| 固定货 + 尽量多装不定量货 | ❌ |

当前最接近 **「多货多柜」的简化版**:给定货与柜,贪心分配柜位装柜,不保证全装完、不优化运费。

---

## 模式一:多货多柜 `multi_multi`

### 用户输入

- **货物**: 若干 SKU,每种 **固定数量**;可选 **从里到外的装柜优先级** (`load_order`)
- **集装箱**: 若干 **备选箱型**,每种可设 **最多可用数量** `max_available`, **单柜运费** `freight_cost`
- **目标**: 用所选箱型 **完全装下** 全部货物,且 **总运费最低**

### 输出

- 最优 (或近优) 箱型组合:如 2×40HQ + 1×20GP
- 每柜 3D 方案、未装完 = 失败 (或报告需加柜)
- 各 SKU 在空间上的装入顺序

### 算法要点 (待实现)

1. **组合搜索**: 在 `max_available` 约束下枚举/启发式搜索箱型数量向量
2. **下界剪枝**: 总体积、总重量、总件数 vs 候选柜容量
3. **内层**: 现有 `Packer` 做可行性 + 利用率评估
4. **目标函数**: `min Σ(count_i × freight_i)`,约束「全部货物已装」
5. **顺序**: `pack()` 前按 `load_order` 排序 items

### 与现网差异

- 需新增柜表字段: `max_available`, `freight_cost`
- 需新增货表字段: `load_order` (里→外,数字小先装靠里)
- API 返回 `plan_summary`: 箱型用量、总运费、是否全装完

---

## 模式二:单货多柜 `single_multi`

### 用户输入

- **一种 (套) 货物**: 尺寸/重量/朝向;「套」= 固定比例的多件 BOM (后续扩展)
- **多种集装箱**: 备选箱型列表 (通常不设上限,或上限很大)

### 输出

- **多种装柜情况** 供用户挑选,例如:
  - 方案 A: 1×40HQ 装 120 件,利用率 78%
  - 方案 B: 2×20GP 各装 65 件
  - 方案 C: 40HQ 与 20GP 混用 …
- 每方案含 3D、件数、利用率、柜数

### 算法要点 (待实现)

1. 对每种箱型 (及常见组合) 求 **单柜最大装载件数** (可二分 + 试装)
2. 生成 **Pareto 前沿**: 柜数少 / 利用率高 / 运费低
3. 不做「多 SKU」分配,只有单一货型重复摆放

### 与现网差异

- UI 限制为单 SKU (或一套 BOM)
- API 返回 `scenarios[]`,前端方案卡片切换,非单一 `containers[]`

---

## 模式三:体积配比 `volume_ratio`

### 用户输入

- **多种货物**: 不指定绝对数量,指定 **体积比** (如 A:B:C = 3:2:1)
- **多种集装箱**: 备选箱型

### 输出

- 多种 **按体积比装填** 的方案,例如:
  - 方案 1: 2×40HQ,A 占 60% 体积,B 30%,C 10%
  - 方案 2: 1×40HQ + 1×20GP,比例维持 3:2:1 …
- 每方案显示实际件数 (由比与单件体积推导)

### 算法要点 (待实现)

1. 将体积比转为 **目标体积份额** 或 **目标件数比** (需约定是否允许非整数件)
2. 搜索柜组合 + 分配各 SKU 件数,使 **实际体积比 ≈ 目标比**
3. 评分: `|actual_ratio - target_ratio|`,兼顾利用率

### 与现网差异

- 货表字段: `volume_ratio` (相对权重),`qty` 可隐藏或作上限
- 输出强调 **比例偏差** 与 **推荐件数**

## 模式四:数量不定 `variable_qty`

### 用户输入

- **多种货物**:
  - **固定数量** `qty_fixed=true`: 必须全部装入
  - **不定数量** `qty_fixed=false`: 尽可能多装
- **一种集装箱** (单箱型,可 `count` 多柜同型)

### 输出

- 固定货 **100% 装入** (否则失败提示)
- 剩余空间内 **不定量货的最大件数** (每 SKU 或合计)
- 3D 与利用率

### 算法要点 (待实现)

1. **阶段一**: 仅固定数量货物装箱,校验是否可行
2. **阶段二**: 对每种不定量货 **贪心或二分** 追加件数直至无法再装
3. 多柜时: 先保证每柜固定货分配,再全局填充不定量

### 与现网差异

- 货表字段: `qty_fixed`
- 不定量货初始 `qty` 可视为 0 或「候选上限」
- 结果展示: `variable_loaded: { SKU: n }`

## 建议 API 结构

```json
{
  "pack_mode": "multi_multi | single_multi | volume_ratio | variable_qty",
  "containers": [{ "name", "length", "width", "height", "max_payload", "count", "max_available", "freight_cost" }],
  "items": [{ "name", "...", "qty", "qty_fixed", "load_order", "volume_ratio" }],
  "support_surface_ratio": 0.7,
  "pack_strategy": "door_last"
}
```

```json
{
  "pack_mode": "multi_multi",
  "success": true,
  "total_freight": 12000,
  "containers": [...],
  "unpacked": [],
  "scenarios": null,
  "variable_loaded": null,
  "plan_summary": { "20GP": 1, "40HQ": 2 }
}
```

`single_multi` / `volume_ratio` 时 `scenarios` 为数组;其余模式可为 `null`。

## 前端 UI 草案

```
[装柜方式 ▼]
  ├ 多货多柜  → 柜表显示「最多数量」「运费」; 货表显示「装柜顺序」
  ├ 单货多柜  → 仅允许一种货; 结果区「方案对比」标签
  ├ 体积配比  → 货表显示「体积比」列,隐藏或弱化「数量」
  └ 数量不定  → 货表「固定/不定」勾选; 单箱型选择提示
```

### 各模式货物可编辑字段 (已实现 UI)

| 字段 | 多货多柜 | 单货多柜 | 体积配比 | 数量不定 |
|------|:--------:|:--------:|:--------:|:--------:|

| 颜色 | ✅ | ✅ | ✅ | ✅ |
| 说明 | ✅ | ✅ | ✅ | ✅ |
| 数量 | ✅ | ✅ | ✅ | ✅ |
| 空间顺序 `load_order` | ✅ | — | ✅ | ✅ |
| 体积比 `volume_ratio` | — | — | ✅ | — |
| 尽量装载 `!qty_fixed` | — | — | — | ✅ |

尺寸/重量/堆叠等仍通过 ⚙ 详情或货物库维护。

1. **多货多柜**: 运费是否仅按箱型单价×数量? 是否含内陆拖车费?
2. **单货多柜**: 「一套货物」是否 = 多种货固定配比装成一套?
3. **体积配比**: 比例按 **体积** 还是 **金额/重量**? 是否允许某 SKU 为 0 件?
4. **数量不定**: 不定量货有 **上限** 吗? 多柜时优先装满一柜还是均衡各柜?

确认后即可按模式逐项实现算法与表单。
